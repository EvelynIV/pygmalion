## 一、原始锐评

这套界面的气质，像“后台模板刷了米白漆，就来参加诗歌展”。对齐还算规矩，但构图、主次和产品辨识度都很弱。

1. **留白留出了毛坯房的感觉。** 投稿管理只有五条记录，却把作品名和状态拉开大半个屏幕，下面再空出一大片。阅读视线要长途奔袭，空间却没提供更多信息。

2. **排版页把最精彩的东西挤进了角落。** 《静夜思》缩在纸张右上方，署名孤零零待在左边，纸面大部分空着；页面上方又被返回入口、标题、描述吃掉一大截。诗已经很小了，界面还在抢它的舞台。

3. **投稿页像办事申请表。** 名字、诗题、正文、方向、字体、落款、署名一路往下排，提交按钮压到 1024 高画面的最底部。右侧明明放着书写示意，却缺少能让人想动手写一首的吸引力。

4. **按钮长度像抽签决定的。** 机器控制页里，“保存串口选择”是一块黑按钮，“把当前位置设为原点”突然变成横跨右侧的大黑条，抬笔、落笔又是两根长条。视觉重量跟操作的重要程度对不上，整个区域像控件摊位。

5. **全都在小声说话，最后谁也听不清。** 灰色说明、细边框、浅色选中态、描边按钮扎堆。克制需要明确的重点，这里很多地方只是统一变淡了。尤其底部“当前书写”和进度，看起来更像版权脚注。

6. **跨页一致性直接露馅。** 投稿管理的侧栏是 208px、顶栏 54px；排版和机器控制却换成 248px、80px。同一个产品切个页面，骨架就膨胀一圈，像几套稿临时拼在一起。

7. **夜间版有种显示器蒙灰的感觉。** 投稿管理几乎整屏都泡在相近的灰绿黑里，层次主要靠细线撑着。它把白天的寡淡完整保留，再调暗了一遍。

最可惜的是，“诗词自动书写”本来很有辨识度，这套界面却让通用表单、列表和设备参数占满了记忆点。用户能记住那些框，未必能记住纸和字。

## 二、补看后的结论与执行边界

补看书写队列、纸张校准、参数设置、结果页、急停和确认界面后，需要把批评进一步落实到以下问题，并准确限定前述判断的适用范围。

1. **混用版本是跨页问题。** 投稿管理与其他页面混用了不同侧栏、顶栏、主题色和字号，改版应先统一共享骨架，再调整每页内容。

2. **灰绿黑的问题主要指深色投稿管理。** 节点 `8:3159` 的投稿管理使用灰绿黑表现；节点 `8:4387` 的深色参数设置已经采用更接近苍渊的黑蓝表现。不能将前面的锐评泛化为全部深色页面都采用同样颜色。应按统一语义变量校正版本漂移。

3. **纸面空白需要区分真实排版与预览构图。** 竖排右起、实际纸张尺寸和实际字号具有业务含义。应优先压缩页面上方的无效空间、改善预览画布比例与显示缩放，而非为了填满画面直接改变诗在纸上的位置或输出尺寸。

4. **队列分组与内容不一致。** 当前“等待书写”中同时出现排队、已完成、失败记录，应分别组织当前任务、等待任务和历史结果。

5. **校准图的边界语义不清。** 需要区分刻度区、纸张、原点、有效书写范围与允许的负偏移。纸张定位有效不自动等于所有作品内容都可书写。

6. **进度语义不能被美化时误改。** 原稿中的百分比是“指令发送进度”。指令发送 100% 与物理书写完成不是同一状态。

7. **已有确认弹窗缺少可核对的信息。** 删除、中止和 GRBL 写入必须给出对应对象、影响及实际变更，而不是只把通用确认框换个标题。

8. **未逐一验证全部画板的动态行为。** 本次依据 Figma 结构和重点截图形成评审，后续执行者需读取现有业务实现，核对控件可用性、参数约束、数据来源和设备状态。不能将设计稿样例当作真实设备结果。

    保留现有产品功能、字段含义、业务状态和设备行为。允许重组页面、压缩重复说明、调整操作位置、统一组件；不要擅自增加登录系统、统计大屏、AI 写诗、作品商城、任务优先级、自动重试等未经确认的功能。

2. **把整个产品统一成一个有明确工作对象的书写工作台。**

    改版后的界面应让用户明确知道：正在处理哪一首诗、纸上的实际效果是什么、接下来可以做什么、机器现在处于什么状态。

    投稿页和结果页突出作品及纸张。投稿管理突出作品的筛选与处理。排版页突出真实预览。队列页突出当前任务。机器控制突出连接与定位。校准页突出纸张和可书写区域的关系。设置页突出参数分组及保存边界。

    通过排版、比例、对齐和明确的操作层级建立气质。避免把每个区域做成同等重要的卡片，也避免为了填满空白增加无用内容。

    诗意主要来自真实字形、纸面比例和作品的呈现。UI 控件使用清晰的无衬线字体；操作文案使用“提交”“保存”“开始书写”等具体词语。

3. **严格统一“苍渊·白垣”主题，并清理现有版本之间的漂移。**

    当前投稿管理与其他页面混用了不同的主题表现。把它们统一到同一套语义变量中，不要继续保留一套灰绿黑、一套黑蓝的深色页面。

    使用以下颜色。组件绑定语义变量，禁止每个画板自行挑选近似颜色。

    | 次级背景 | `#F3F1EA` | `#0B0F13` |
    | 控件与独立表面 | `#FCFBF8` | `#111820` |

    | 悬停背景 | `#EDF1EE` | `#16212A` |
    | 普通边框 | `#D8DCD7` | `#273746` |

    | 主文字 | `#252A2A` | `#E7EEF4` |

    | 辅助色 | `#858D89` | `#7C8B98` |

    功能状态色统一为：成功 `#6F8F83`、警告 `#B09464`、危险 `#A96F74`、信息 `#607D99`。

    状态色优先用于图标、标记和局部边框，状态文字使用满足对比度的文字颜色。不要默认把浅灰辅助色用于所有小字号说明。

    浅色界面要看得出页面、纸张工作区、输入控件之间的边界。深色界面要看得出主背景、侧栏、操作表面、选中区域之间的层级，不能整屏铺成相近的暗色。

    两套主题共享布局、尺寸、组件结构、操作位置和状态逻辑。主题切换不能造成内容跳动。

    主题控件统一使用“浅色”“深色”或对应图标及明确提示，不要在不同页面混用“白昼”“白垣”“夜间”“苍渊”作为不同的按钮名称。

4. **重建统一的工作区骨架，彻底消除跨页尺寸变化。**

    在宽度不少于 1280px 的桌面界面中，工作区侧栏统一为 248px，顶栏统一为 64px，底部任务栏统一为 56px。这些尺寸必须由共享组件控制。

    侧栏顶部品牌区与顶栏等高。品牌名使用 18px 左右、600 字重；产品描述使用 12px 次文字。侧栏左右内边距为 16px，导航项高 40px，项目间距 8px，图标为 18–20px。

    导航顺序固定为：投稿管理、书写队列、机器控制、纸张校准、参数设置。机器控制和纸张校准使用能区分含义的图标，避免两个项目使用几乎相同的图形。

    当前导航通过选中背景、主文字和图标共同表达。非当前项目保持清晰可读，不要过度降低透明度。

    顶栏左侧显示简洁的位置路径，右侧放置必要的设备状态、主题切换和全局急停。页内业务按钮不随意塞进全局顶栏。

    全局急停固定在顶栏右侧，保持所有工作区页面位置一致。整理当前顶栏、正文、底栏中的重复急停入口，底栏主要承担当前任务状态和中止操作。沿用现有急停触发行为，不增加阻碍操作的装饰动画或额外确认步骤。

    工作区主内容左右默认内边距 32px，顶部间距 24px。共享内容容器最大宽度为 1280px；窄一些的表单在容器内部限制宽度并左对齐，不要每个页面分别居中造成左边线跳动。

    页标题区域控制在约 64px，标题与说明之间为 8px，标题区域与主体之间为 24px。删除当前“返回按钮、标题、说明各占一整行，再分别空出大间距”的堆叠方式。

    底部任务栏显示任务名称、作者、真实状态和适用的进度。没有任务时显示“当前无书写任务”。设备不可用时显示真实设备状态。底栏不会遮挡正文最后一行、按钮或输入框。

    成员投稿入口使用共享的分享组件。侧栏底部提供入口，投稿管理中提供快捷入口，地址和复制逻辑复用同一组件；不要重复铺开多组地址、说明和大按钮。

5. **统一字体、间距、按钮和表单组件。**

    中文 UI 使用思源黑体、Noto Sans SC 或一致的系统无衬线字体；西文与数字使用 Inter 或一致的系统字体。真实书写预览继续使用现有字库和字形结果。

    页面标题采用 28px/36px、600 字重；区块标题采用 18px/26px、600 字重；正文、输入值和普通按钮采用 14px/22px；元数据采用 12–13px/18px。状态、错误原因和影响操作的说明不能缩得比普通辅助文字更小。

    间距以 8px 为基准。标签与控件之间 8px，字段之间 16px，分组之间 24–32px，同组按钮之间 8–12px。

    常规输入框和按钮高 40px，紧凑操作高 32px。常规圆角 8px，大容器最多 12px，边框为 1px。

    普通按钮水平内边距 16px，宽度由文字及必要的最小宽度决定。禁止把“抬笔”“落笔”“设为原点”随手拉成数百像素的长条。满宽按钮只用于明确的窄栏提交区域。

    区分主按钮、次按钮、文字操作和危险操作。每个独立任务区域只有一个明确的主操作；不同区域同时出现主按钮时，必须体现当前操作阶段，不能让它们一起争夺注意力。

    输入框的单位统一右对齐，输入值不会与单位重叠。数字采用一致的小数精度；精度与范围沿用业务规定，不随意修改。

    分段选择器必须有完整组件边界、清晰选中态和一致的点击区域，不能把左半边做成按钮、右半边做成漂浮文字。

    所有基础组件补齐默认、悬停、聚焦、按下、禁用、处理中和错误状态。普通文字对比度至少 4.5:1，大字至少 3:1，焦点清晰可见。

6. **完整重做投稿页，让填写与效果示意组成一个紧凑工作区。**

    当前投稿页的问题是字段一路向下堆叠，右侧示意与填写过程联系弱，提交动作被挤到屏幕底部。

    公开投稿页保留独立顶栏，不使用管理侧栏。顶栏高 64px，左侧为品牌，右侧为主题切换和现有工作区入口。

    主内容最大宽度约 1184px。在 1440px 桌面宽度下，左侧表单约 528px，右侧效果区域使用剩余宽度，两栏间距 24px。标题和说明合并为紧凑的引导区，不做大型宣传首屏。

    左侧字段按以下顺序布局：第一行“你的名字”和“诗题 · 选填”并排；第二组为正文；第三组为排版方向；第四组将字体与落款方式并排；第五组根据落款方式显示署名；最后放置提交动作。

    正文输入框默认高约 176–192px，允许内部滚动。字数与换行说明放在输入框下方的一行中，不分别占据大块高度。保留现有 2000 字限制及其计数规则。

    方向选择用统一的分段控件，清楚表达“竖排右起”和“横排”。选择状态不能只靠细微色差。

    选择不使用落款时，相关署名字段按业务规则隐藏或禁用；不要保留一个看起来还能填写但不会产生效果的字段。

    “提交诗词”使用明确的主按钮，宽约 160–192px。在 1440×900 的默认状态下，主按钮应能出现在首屏中，不能依靠减小文字或隐藏必填项达成。

    右侧以纸张为核心，减少宽大容器内部的无效空白。纸张保持真实 A4 比例，画布中的纸张居中放置，示意标题和简短说明分别在上方与下方。

    保持“效果示意”与“实际预览”的边界。现有界面如果只支持静态示意，就明确标注示意，不伪装成随输入实时更新的真实结果。只有已有能力支持时才设计实时更新。

    字体名称、落款方式等技术信息可以保留，但不要让字库解释压过填写任务。

    校验失败时，错误显示在对应字段旁，保留用户内容，焦点定位到第一个错误。提交中时防止重复提交，按钮显示处理中；提交失败后允许使用保留的内容重试。

7. **重做投稿结果页，把成功信息、作品和下一步组织在一起。**

    当前结果页重复表达“诗词已提交”和“投稿成功”，再用一条很宽的提示框切断内容，右侧只剩少量文字和按钮。

    将重复成功信息合并为一处：一个状态图标、一句明确的“诗词已提交”，下方显示投稿编号、作品名和作者。避免再添加横跨整页的成功横幅。

    主体采用作品预览与结果信息并列的结构。纸张预览约占主体宽度的 55%–60%，信息区域约占 40%–45%，间距 32px。

    纸张应比投稿页的示意更突出，并保持完整比例。作品信息区包含提交结果、排版方向、字数、字体等现有元数据。

16. **给出完整的宽度与高度适配，避免只在 1440×1024 上成立。**

    至少检查 1024×768、1440×900、1440×1024、1920×1080。

    1280px 及以上采用 248px 侧栏。1024px 等较窄桌面宽度使用统一的紧凑导航方案，例如 72px 图标栏加可展开导航；所有工作区页面在相同宽度采用相同规则。

    图标导航必须提供可访问名称和明确提示，不能让用户仅靠猜图标识别页面。

    排版页在窄桌面中可将参数栏收至约 288px；预览按可用高度等比缩放。参数较长时允许独立滚动，但主要执行按钮始终可达。

    投稿表单空间不足时由双栏转为单栏。正文和提交动作优先，效果示意不能把提交动作推到很远的位置。

    列表优先保留作品、状态与主要操作，次要元数据可合并或隐藏。正文不能缩成难读的小字来塞进所有列。

    1920px 宽度下遵守内容最大宽度，不能把作品名和状态继续拉远，也不能把短数值输入框放大到半屏。

    长作品名、长作者名、长字体名、长地址和长错误消息分别检查。截断的内容应能查看完整值，换行不能与按钮、单位或状态重叠。

    本次主要交付桌面改版及窄桌面适配。不要未经检查就重做文件中其他页面的移动端设计。

17. **用真实组件和约束制作 Figma，不交付只能截图的摆放稿。**

    先建立统一的工作区骨架、按钮、输入框、分段控件、筛选标签、列表行、状态、提示、弹窗和纸张预览组件，再用实例组成页面。

    相关内容使用 Auto Layout。明确固定宽度、自适应宽度和内容高度。长文字、字段隐藏、错误出现、计数变化时，布局仍然成立。

    建立浅深两种语义模式并绑定变量。组件不能通过手工复制和逐项改色实现主题。

    动态文字保留为文字图层；真实字形预览继续使用已有生成结果。不要把整页栅格化，也不要把所有标题和说明转为轮廓来逃避字体与布局问题。

    对新组件使用清楚的名称和变体。区分组件基础定义与页面实例，不随手修改公共组件导致旧稿全部漂移。

    原型至少串联投稿到结果、投稿管理到排版、排版到队列、机器控制到校准，以及设置预览到写入确认。不存在的业务动作不能用成功跳转假装完成。

    交付页面清单、旧新节点对应关系、使用的共享组件和主要布局规格，供后续实现直接核对。

18. **按以下标准验收，全部检查后再交付。**

    同一宽度下，所有工作区页面侧栏、顶栏、底栏、内容左边线和主操作规格一致。

    两套主题只切换颜色与对应表面表现，不改变布局和功能。

    投稿页的默认桌面首屏能看到提交动作；结果页同时看清提交状态、作品及下一步。

    投稿管理的作品、状态和操作扫描路径紧凑，剩余数据有真实查看方式。

    排版页首屏能看到真实纸张预览、关键参数和开始书写入口；查看缩放不会改变实际字号、纸张比例或排版。

    队列清楚区分当前、等待和历史结果；指令发送 100% 不等于书写完成。

    机器控制的控件尺寸一致，可用状态与设备状态匹配；急停入口位置稳定。

    校准图的比例、坐标和边界关系准确，允许负偏移的规则没有被误改。

    软件保存、备份、写入预览和 GRBL 写入确认的边界清楚。

    所有错误状态保留合理上下文；加载状态不会使关键区域跳动；长文本和窄桌面没有遮挡或溢出。

    不存在可点击但无功能的数据控件、虚构设备状态或伪造实时预览。

    如果任何一项未通过，继续调整对应页面及其共享组件，并检查受影响的浅深主题和状态。

    最终交付应包括全部主页面、现有状态、弹窗与适配稿。不能用“已优化风格”代替逐页完成和实际核对。
